# Gateway

A Gateway is an organization-level infrastructure component that routes traffic through a controlled proxy — every **[LLM Service Provider](./llm-service-provider.mdx)** and **[MCP Proxy](./mcp-proxy.mdx)** is exposed to agents through a gateway's invoke URL, rather than being called directly. Agent Manager currently supports the **WSO2 AI Gateway**.

Unlike Organization, Project, and Environment, the Gateway isn't an OpenChoreo abstraction. It's a [WSO2 API Platform](https://github.com/wso2/api-platform) component that Agent Manager registers and manages on top of OpenChoreo's infrastructure.

## Why Traffic Goes Through a Gateway

Routing LLM and MCP traffic through a gateway rather than exposing upstream providers directly gives Agent Manager one place to apply cross-cutting controls:

- **Authentication** — agents authenticate with platform-issued API keys instead of upstream provider credentials.
- **Access control** — which API operations or MCP tools/resources/prompts an agent can reach.
- **Rate limiting** — request and token thresholds enforced at the gateway, protecting the upstream provider.
- **Guardrails** — content safety policies attached to a provider or agent.

## Per-Environment Deployment

A gateway is registered at the organization level, but it deploys one artifact per **[Environment](./environment.mdx)** it's active in. When you register an LLM Service Provider or MCP Proxy, the platform deploys that resource's configuration to whichever gateway is currently active for each environment — you don't manually wire a provider to a gateway per environment yourself.

## Ingress and Egress Gateways

A single environment can run two gateways with different traffic directions: an **ingress** gateway that faces incoming calls to your agents, and an **egress** gateway that faces outbound calls to your model providers. Splitting the two lets each be scaled and hardened independently, since inbound and outbound traffic rarely share the same load or threat profile.

## Relationship to Other Concepts

- **[LLM Service Providers](./llm-service-provider.mdx)** and **[MCP Proxies](./mcp-proxy.mdx)** are registered independently of any gateway, but each deploys its per-environment configuration to that environment's active gateway.
- Multiple gateways can exist in one organization (for different environments or teams); each LLM Service Provider is exposed through whichever gateway serves its environment.
